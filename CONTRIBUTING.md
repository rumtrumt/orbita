# Как вносить изменения

## Подготовка

```bash
uv sync --extra gpu
uv run playwright install chromium   # только для живого голосового прогона
ollama pull qwen3:4b                 # для тестов с моделью и оценки NLU
```

## Перед коммитом

```bash
uv run ruff format src tests evals
uv run ruff check src tests evals
uv run mypy
uv run pytest
```

CI выполняет те же проверки, кроме тестов с настоящими моделями.

## Правила проекта

- Арифметика дат живёт только в `nlu/temporal/parser.py`.
- Новая реплика сначала добавляется в `tests/golden/nlu.yaml`, потом поддерживается в правилах.
- `evals/nlu_holdout_2.yaml` только измеряет качество. Под него нельзя настраивать правила и промпт,
  иначе оценка перестанет быть честной.
- Модель не меняет существующие записи без указания на них в реплике.
- Значимые решения фиксируются в `docs/adr`.
- Схема БД меняется только через миграцию Alembic.

## Коммиты

Сообщение описывает изменение в повелительном наклонении и начинается с типа: `feat`, `fix`,
`docs`, `test`, `refactor`, `chore`.
