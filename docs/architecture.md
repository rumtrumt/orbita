# Архитектура

## Путь реплики

1. Браузер записывает голос через MediaRecorder и останавливается по тишине. Текст идёт сразу в
   шаг 3.
2. `POST /api/voice` отвечает потоком NDJSON: интерфейс видит этапы «распознаю», «думаю», а не один
   долгий спиннер. PyAV декодирует запись, Whisper распознаёт её. Галлюцинации на тишине вроде
   «Субтитры сделал...» отсекаются, вероятность отсутствия речи учитывается.
3. `Assistant.turn` открывает транзакцию и передаёт текст в `DialogManager`.
4. Если ассистент ждёт ответа на вопрос, реплика сначала проверяется как ответ. Самостоятельная
   команда отменяет вопрос и выполняется как обычно.
5. `HybridInterpreter` получает команду от правил. При уверенности ниже 0,85 подключается LLM, её
   ошибка или недоступность возвращают к правилам, а LLM отключается на 60 секунд.
6. Менеджер проверяет полноту и корректность, ищет конфликты и выполняет действие через сервисы.
7. Ответ существует в двух видах: компактный текст на экране и развёрнутый для синтеза («15:00»
   становится «пятнадцать ноль ноль», «31 октября» становится «тридцать первого октября»).

## Состояние диалога

`DialogState` хранится в БД и поэтому переживает перезапуск:

- `focus` — записи, о которых шла речь: на них указывают «её», «вторую», «эту задачу»;
- `has_last_list`, `last_list_kind` — параметры списка, чтобы понять «а на завтра?»;
- `pending` — незавершённое действие. Типы: `slot` (не хватает данных), `past` (время прошло),
  `conflict` (занято), `choose` (несколько совпадений), `move` (не сказано куда),
  `bulk_delete` (подтверждение).

Непонятый дважды вопрос снимается: ассистент не должен застревать в одном состоянии.

## Модель данных

| Таблица | Назначение |
|---|---|
| `users` | профили, хеши токена и PIN (scrypt), токен календаря |
| `items` | записи: тип, название, локальные дата и время, длительность, срок, статус, правило повторения, момент напоминания |
| `item_revisions` | снимок записи до изменения; на нём держится «отмени» |
| `item_embeddings` | векторы названий |
| `dialog_states` | состояние диалога |
| `messages` | история разговора |

Повторения хранятся в формате RRULE (RFC 5545) и разворачиваются при чтении. Выполнение
повторяющейся задачи переносит её на следующее вхождение.

## Отказоустойчивость

| Сбой | Поведение |
|---|---|
| Нет LLM | работают правила; поиск использует консервативный порог |
| Нет модели эмбеддингов | остаётся лексический поиск |
| Нет CUDA | Whisper переходит на CPU |
| Нет Whisper | сообщение с просьбой написать текстом |
| Нет Piper | озвучивает браузер |
| Перезапуск сервера | уточнения, история и напоминания сохраняются в БД |
